## Hexo 二级路径配置修复

### 问题描述
用户部署 Hexo 站点到 GitHub Pages 子目录时，静态资源无法正确加载，因为资源路径指向根目录而非子目录。

### 根本原因
Hexo 主配置文件 `_config.yml` 中 `root` 设置不正确：
- **错误配置**：`root: /`
- **正确配置**：`root: /dcm-blog/`（当站点部署到 `https://username.github.io/dcm-blog/` 时）

### 修复步骤
1. 修改 `_config.yml` 第 17 行：`root: /dcm-blog/`
2. 执行 `hexo clean && hexo generate` 重新生成站点
3. 验证生成的 HTML 文件中资源路径已包含 `/dcm-blog/` 前缀

### 验证结果
- ✅ CSS 路径：`/dcm-blog/css/style.css`
- ✅ JS 路径：`/dcm-blog/js/search.js`
- ✅ 图片路径：`/dcm-blog/img/logo.png`
- ✅ 本地服务器测试：HTTP 200 正常响应

### 经验总结
**Hexo 部署到子目录的正确配置**：
```yaml
url: https://username.github.io/project-name
root: /project-name/
```

这个配置适用于所有 GitHub Pages 项目站点（非组织/用户主页）。

## 搜索功能子目录路径修复

### 问题描述
`search.xml` 的 fetch 路径硬编码为 `/search.xml`，在子目录部署时导致 404（实际路径应为 `/dcm-blog/search.xml`）。

### 修复方案

**1. `themes/dcm-theme/layout/_widget/search.pug`**
在搜索输入框上添加 `data-root` 属性，将 Hexo 的 `config.root` 传递到前端：
```pug
input#search-input.search-input(type="text", placeholder="搜索...", data-root=config.root || '/')
```

**2. `themes/dcm-theme/source/js/search.js`**
读取 `data-root` 属性拼接正确路径：
```javascript
const searchXmlPath = (searchInput.getAttribute('data-root') || '/') + 'search.xml';
fetch(searchXmlPath)
```

### 验证结果
- ✅ `public/index.html` 中 `data-root="/dcm-blog/"`
- ✅ `public/js/search.js` 路径拼接逻辑正确
- ✅ 本地服务器 `http://localhost:4000/dcm-blog/search.xml` 返回 200
- ✅ `hexo generate` 无 Pug 语法错误

### 经验总结
在 Hexo 主题中向前端 JS 传递配置值，推荐用 `data-*` 属性，避免 Pug 模板中嵌入脚本的转义问题。
