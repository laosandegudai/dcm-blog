## 修复：SCSS 编译错误和颜色值异常

### 问题
用户报告"样式异常"。执行 `hexo generate` 后发现：
1. `color.adjust()` 函数报错：`There is no module with the namespace "color"`
2. CSS 文件 `public/css/style.css` 为 0 字节
3. `a:hover` 的颜色值为错误的 `rgb(37.2191780822, 105.7808219178, 177.2808219178)`

### 原因
- 在 `_layout.scss` 中使用了 `color.adjust()`，但因为使用的是 `@import` 而不是 `@use`，所以 `color` 模块没有被加载
- `darken()` 函数在计算颜色时出错（可能是 `$primary-color` 值有问题）

### 修复
1. 将 `_layout.scss` 第 184 行的 `color.adjust($primary-color, $lightness: -10%)` 改回 `darken($primary-color, 10%)`
2. 将 `_variables.scss` 和 `_layout.scss` 中的所有 `darken()` 函数调用改为固定颜色值：
   - `$link-hover-color: darken($primary-color, 15%)` → `$link-hover-color: #2d5fa6;`
   - `background-color: darken($primary-color, 10%)` → `background-color: #2d5fa6;`
3. 删除 `public/css/style.css` 后重新生成

### 结果
- SCSS 编译成功，无错误
- `public/css/style.css` 生成成功（17306 字节）
- `a:hover` 的颜色值正确（`#2d5fa6`）
- Hexo 本地服务器运行在 `http://localhost:4000`

## 优化：搜索组件极简化

### 需求
用户要求"搜索只显示一个输入框不需要占用这么多行"。

### 实现方案
将搜索结果改为浮动下拉层，不占用布局空间：

1. **修改 `search.pug`**：
   - 只保留输入框
   - 添加 `.search-input-wrapper` 包裹输入框和结果容器
   - 结果容器 `.search-result` 初始为空

2. **修改 `_layout.scss`**：
   - `.search-widget` 添加 `position: relative`
   - `.search-result` 改为绝对定位（`position: absolute`），默认隐藏（`display: none`）
   - 添加 `.search-result.active` 类控制显示
   - 精简输入框样式：内边距 6px 12px，字体 0.8rem，圆角 15px

3. **修改 `search.js`**：
   - 添加 `active` 类的添加/移除逻辑
   - 输入框获得焦点时显示提示
   - 点击页面其他地方时隐藏搜索结果

### 效果
- 侧边栏中的搜索组件只显示一个紧凑的输入框
- 输入关键词后，搜索结果以浮动下拉层显示，不占用布局空间
- 点击其他地方，下拉层自动隐藏

### 文件变更
- `themes/dcm-theme/layout/_widget/search.pug`
- `themes/dcm-theme/source/css/_layout.scss`
- `themes/dcm-theme/source/js/search.js`
